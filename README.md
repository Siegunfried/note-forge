# Note Forge — 速记整理助手

> 用符号标记课堂速记，AI 自动补全成完整结构化笔记。VS Code 插件。

## 这是什么

上课时你只需要用**关键词 + 12 个符号**记下要点，按 `Ctrl+Enter`，插件会：

1. 按内置的整理规则（符号表 + 提示词）逐行解析你的速记
2. 把纯内容交给 DeepSeek（或任意 OpenAI 兼容接口）补全展开
3. 返回结构完整、标注清晰的 Markdown 笔记，写到同名的 `.md` 成品（你的 `.forge` 原样保留）

成品里只有 AI 补全处标【补】，其余不加冗余标注，质感干净利落。

## 工作流

```
上课记速记  xxxx.forge
    │  Ctrl+Enter（整理）
    ▼
成 品     xxxx.md
    │  也可从侧边栏「章节」选中某章 → 重新生成 / 重构
    ▼
导入 PDF  侧边栏「导入」→ 生成同名 xxxx.forge 供审阅
```

## 12 个符号

标记只在**行首**生效；一行可叠加不同类别的符号（每类至多 1 个）。

| 符号 | 名称 | 类别 | 含义 | 助手处理 |
|------|------|------|------|---------|
| `#` | 标题 | 结构 | 章节标题 / 主题起点 | 作为层级标题，统领其下所有子条目 |
| `%` | 思考 | 结构 | 自己的思考 / 批注 | 转成注释（引用块旁批） |
| `?` | 疑问 | 结构 | 有疑问 / 拿不准 | 引用块旁批：详细解答 + 注明依据 |
| `_` | 补全 | 内容 | 没记完 / 没记全 | 按结构补全，补全处标【补】 |
| `$` | 定义 | 内容 | 给术语/概念下定义 | 严格定义 + 通俗解释 |
| `~` | 公式化 | 内容 | 把陈述/命题/证明转严格形式 | 主体只含数学·逻辑·公式·代码，文字仅作旁批 |
| `*` | 深挖 | 内容 | 特别深入展开 | 函数→语法·用法·注意；代码→结构·作用；命题→严格证明 |
| `@` | 链接 | 内容 | 超链接 / 文档地址 / 图片 | 转 Markdown 链接 `[说明](地址)`；图片则 `![说明](地址)` |
| `=` | 举例 | 形式 | 举例说明 | 补充 / 整理具体例子 |
| `&` | 对比 | 形式 | 易混淆 / 并列概念 | 必须生成对照表（列对齐、逐项对比） |
| `!` | 重点 | 修饰 | 重点 | 加粗突出，不得丢失 |
| `+` | 没听懂 | 标注 | 课上没听懂，课后需补 | 纯个人标记：不影响正文输出，章节树中显示红色警告 |

- **`##`**：纯章节标题，仅用于结构层级划分，不生成任何正文。
- 无符号行 = `#`（标题）的简写。
- 组合规则：一行 = `[结构?] + [内容?] + [形式?] + [修饰?] + [标注?]`。

## 两条数据流

`.forge` 是**原文速记**（只读），`.md` 是**成品笔记**（只写）：

| 你在哪个文件按 | 原文读哪 | 成品写到哪 |
|---|---|---|
| `xxx.forge` | `xxx.forge` 全文 | 同名 `xxx.md`（新建/覆盖），`.forge` 分毫不动 |
| `xxx.md`（旁边有同名 `.forge`） | 同名 `.forge` 全文 | 覆盖当前 `xxx.md` |
| 普通 `.md`/txt（无 `.forge`） | 选区 / 全文 | 就地整理（兼容） |

## 功能

- 🎨 **符号高亮**：标记符号在行首自动着色（跟随当前主题）
- ⚙️ **语法诊断**：`.forge` 的符号组合错误实时波浪线 + 问题面板提示
- 📄 **PDF 导入**：把一个 PDF 生成同名 `.forge`（文本型直接抽文字；扫描型走视觉 OCR），生成后交你审阅
- 🌲 **章节树**：侧边栏展示章节层级，选中后可「重新生成」某章（可写自定义要求）
- 🔀 **章节树智能重构**：AI 按知识逻辑重排章节的层级与顺序，**只调结构、不动任何节点内容**
- ↺ **回退 / 前进**：对重构操作保留三步历史，可来回切换
- 🔌 **可换模型**：默认 DeepSeek，也可指向任意 OpenAI 兼容接口

### 侧边栏

- **笔记**：符号速查（按类别分组）+ 新建 / 整理 / 设置快捷入口
- **章节**：章节树选中 + 重新生成 / 重构 / 回退 / 前进
- **导入**：导入 PDF 生成速记的醒目入口

## 命令

| 命令 | 快捷键 | 说明 |
|------|--------|------|
| 整理当前笔记（补全） | `Ctrl+Enter` | 把 `.forge` 速记整理成 `.md` 成品 |
| 新建速记 | — | 新建 `.forge` 文件 |
| 导入 PDF 生成速记 | — | 文本型 / 扫描型双通道，生成同名 `.forge` |
| 重新生成 | — | 对选中章节（可带自定义要求）局部重新生成 |
| 重构章节树 | — | AI 重排章节层级与顺序，不动内容 |
| 回退 / 前进 | — | 在重构历史快照间切换（保留三步） |

## 配置

在设置（或 `settings.json`）里：

| 项 | 默认 | 说明 |
|----|------|------|
| `noteForge.apiKey` | （空） | API Key；留空读环境变量 `DEEPSEEK_API_KEY` |
| `noteForge.apiBaseUrl` | `https://api.deepseek.com/chat/completions` | OpenAI 兼容地址 |
| `noteForge.model` | `deepseek-flash` | 模型名（质量优先可换 `deepseek-v4-pro`） |
| `noteForge.maxTokens` | `16384` | 单次输出 token 上限 |
| `noteForge.temperature` | `0.3` | 采样温度 |
| `noteForge.structureModel` | （空） | PDF/文档结构化专用模型；留空复用 `model` |
| `noteForge.ocrModel` | （空） | 扫描版 OCR / 视觉多模态模型（支持图片输入） |
| `noteForge.ocrApiKey` | （空） | OCR / 视觉模型 Key；留空复用 `apiKey` |
| `noteForge.ocrBaseUrl` | （空） | OCR / 视觉模型 OpenAI 兼容地址；留空复用 `apiBaseUrl` |
| `noteForge.ocrMaxPages` | `15` | 扫描版 PDF 仅渲染识别前 N 页（控成本） |

## 项目结构（模块分层）

```
src/
├─ extension.ts             # 入口：注册命令与视图
├─ config/settings.ts       # 配置读取
├─ core/                    # 纯逻辑，无 VSCode 依赖，可单测
│  ├─ symbols.ts            # 12 符号唯一定义（单一事实来源）
│  ├─ forgeTree.ts          # .forge 树解析
│  ├─ apiClient.ts          # OpenAI 兼容 HTTP（流式 + 视觉）
│  ├─ organizer.ts          # 编排：拼提示词 → 调 API → 拼装
│  ├─ chapterReorder.ts     # 章节树智能重构（只调层级/顺序）
│  ├─ treeHistory.ts        # 回退 / 前进三步历史栈
│  ├─ pdfImport.ts          # PDF 结构化模型 + Forge 映射
│  ├─ pdfExtractor.ts       # pdfjs-dist 文本提取
│  ├─ pdfRender.ts          # @napi-rs/canvas 页面渲染 → PNG
│  └─ dynamicImport.ts      # 打包安全的动态导入 + workerSrc
├─ commands/
│  ├─ organize.ts           # 整理 / 重新生成 / 重构 / 回退前进
│  ├─ importPdf.ts          # PDF 导入流程编排
│  ├─ create.ts             # 新建速记
│  └─ settings.ts           # 设置菜单
└─ views/                   # 侧边栏树（笔记 / 章节）
syntaxes/
└─ notes.tmLanguage.json    # 符号高亮
```

## 已知边界

- `@` 直接把地址转成 Markdown 链接/图片，不读取所引用资料内容进行补充；联网检索见 Roadmap。
- 高亮色由主题决定（复用通用 TextMate 作用域）。
- 扫描型 PDF 的 OCR 依赖视觉多模态模型，需配置 `noteForge.ocrModel`（及对应的 key / baseUrl）。
- 生成的文档与源 PDF 主文件名一致，一次只导入单个 PDF（`ocrMaxPages` 控制扫描版页数上限）。
